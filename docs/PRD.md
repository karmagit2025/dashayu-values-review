## 1. 背景与问题

公司年度价值观考核目前用一张 A4 纸：6 个价值观 × 5 级行为锚定（通关制），员工自评打勾、写例证，主管再评一遍，HR 收表汇总。

纸质流程的四个堵点：

1. **发放和回收靠人**：打印、发、催、收，一圈下来一两周，总有人丢表、拍糊、写错栏。
2. **分派靠记忆**：谁归哪个主管评，HR 得对着组织架构一个个派，跨部门/代管的情况经常漏。
3. **汇总靠手抄**：几十号人的分数要一格格敲进 Excel，容易错行，且没有部门维度。
4. **版式不友好**：原表例证栏是竖长条，打印出来没法写；一页塞不下，要翻页。

## 2. 产品目标

| 目标 | 衡量方式 |
|---|---|
| 员工自助完成自评，不用 HR 逐个建单 | 新员工从打开发链接到提交 ≤ 5 分钟，HR 零干预 |
| 提交后自动落到对应主管，不用人工分派 | 主管打开链接即看到待评名单，覆盖率达到 100% |
| 导出即可归档/打印 | 导出的 Excel 与纸质版同版式，一页 A4 |
| 数据不出内网 | 单机 SQLite，无第三方 SaaS 依赖 |

**非目标（本期不做）**

- 不做 360 度环评、不做 KPI/OKR 对接、不做薪酬联动
- 不做账号体系：员工和主管都靠「链接 + token」进入，不设密码
- 不做移动端 App / 小程序（H5 自适应即可）

## 3. 用户与角色

| 角色 | 场景 | 权限 |
|---|---|---|
| **员工** | 收到入口链接 → 登记 → 自评 → 提交 | 只能看/改自己那一份（提交后锁定） |
| **主管** | 收到专属链接 → 看「待我评价」→ 逐个评价 | 只能看自己部门树下的员工；只能写他评部分 |
| **HR / 行政** | 维护部门与主管、开关入口、导出、处理异常 | 后台全量（密码进入） |
| （未来）校准人 | 校准会现场调分 | ⏳ 待设计 |

## 4. 核心流程

```
HR 配置组织（部门树 + 部门主管）
        │
        ▼
发入口链接 → 员工填手机号/姓名/选部门 → 自评（6 项，4-5 分需例证）→ 提交
                                                                  │
                                    系统按「部门 → 最近一级主管」自动归属
                                                                  ▼
主管打开专属链接 → 待我评价名单 → 点人 → 看自评 → 填他评 + 综合分 → 提交
                                                                  │
                                                                  ▼
                                                        HR 导出（单人 / 批量）
```

**状态机**

```
draft ──员工提交──▶ submitted ──主管提交──▶ done
  ▲                    │
  └──────HR 重置────────┘
```

- `draft`：员工可反复修改（自动存草稿）；主管打不开（403）
- `submitted`：员工自评锁定；主管可评价；HR 可重置回 draft
- `done`：双方锁定；HR 可导出；如需修改只能重置

## 5. 功能需求

### 5.1 员工入口（FR-E）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|

| FR-E-02 | 员工填写手机号（11 位校验）、姓名（2–20 字）、从预设部门树中选部门 | P0 | ✅ |
| FR-E-03 | 提交后直接进入自评页，无需注册/登录 | P0 | ✅ |
| FR-E-04 | 同一手机号 + 同一周期重复进入时，回到原记录继续填，不新建 | P0 | ✅ |
| FR-E-05 | 同一手机号但姓名不同，拒绝并提示联系 HR（防冒填） | P1 | ✅ |
| FR-E-06 | 入口可一键关闭；关闭后拒绝新登记，已提交的主管照常评价 | P1 | ✅ |
| FR-E-07 | 员工自选部门若有误，HR 可在后台直接改，主管归属自动重算 | P1 | ✅ |

**验收**：输入非法手机号/空姓名/未选部门均有明确提示；同一手机号第二次进入能看到上次的草稿内容。

### 5.2 自评（FR-S）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-S-01 | 按 6 个价值观分卡片展示，每个价值观 5 条行为锚定（1–5 级递进） | P0 | ✅ |
| FR-S-02 | 每项点选一个级别（单选），选中态高亮 | P0 | ✅ |
| FR-S-03 | 选中 4–5 分时强制填写例证（≥ 8 字），3 分及以下选填 | P0 | ✅ |
| FR-S-04 | 实时进度「已完成 x/6」，顶部吸顶 | P1 | ✅ |
| FR-S-05 | 草稿自动保存在本地，关页面/切后台不丢 | P0 | ✅ |

| FR-S-07 | 提交后自评锁定，重开链接只读展示 | P0 | ✅ |
| FR-S-08 | 完成后给出结果摘要（6 项自评分） | P2 | ✅ |

**业务规则**：采用通关制，勾选"所达到的最高级别"；前面小分值未达到时，后面的分数不计。

## 6. 数据模型

```
departments(id, name, parent_id, manager_id, sort)
managers(id, name, phone, token)
reviews(id, period, emp, phone, dept_id, mgr_id,
        emp_token, mgr_token, status, answers,
        created_at, emp_at, mgr_at)
settings(k, v)   -- period / entry_open
```

`answers` 为 JSON 数组，长度 6（每个价值观一项）：

```json
[{"self": 4, "self_note": "……", "mgr": 4, "mgr_note": "……", "final": 4}, ...]
```

> 设计取舍：`answers` 存 JSON 而不是 30 行明细表——本期只需要"整份读、整份写"，JSON 能减少 90% 的联表代码；后续要做逐条统计时再拆表（见路线图）。

## 9. 异常与边界

| 场景 | 当前处理 | 备注 |
|---|---|---|
| 员工忘提交就关页面 | 本地草稿 + 同手机号再进续填 | 换手机/清缓存会丢，属可接受 |
| 员工选错部门 | HR 后台改，主管归属重算 | 已实现 |
| 部门没设主管 | 记录显示"未指定"，无人认领 | 后台列表红色提示，需 HR 补 |
| 主管离职/换人 | 部门改挂新主管，历史记录随之迁移 | 打开主管链接时自动补正 |
| 同名员工 | 以手机号区分 | 导出 sheet 名冲突时加后缀 |
| 主管代填员工自评 | 技术上可以（告知手机号即可） | 内网信任模型，暂不加验证 |
| 重复提交 | 服务端 403 | 已覆盖 |

## 10. 非功能需求

- **兼容**：移动端 390px 起、桌面 1440px；Chrome / Edge / Safari / 微信内置浏览器
- **性能**：500 人规模，列表与队列接口 < 300ms（SQLite 单机足够）
- **可用**：单进程 uvicorn 即可；数据库文件即备份
- **隐私**：手机号、评价属个人信息；内网部署，不接外部服务；公网需 HTTPS
- **可维护**：考核内容集中在 `content.py`，改标准不动代码逻辑

## 12. 路线图

**P1（下一版，建议 1–2 周）**
1. 催办：待评价超过 N 天，企业微信机器人/邮件提醒主管
2. 退回修改：主管可退回员工重填；HR 可指定某段重开
3. 部门/人员从 HR 系统同步，避免员工选错部门
4. 导出按部门筛选、生成部门对比

**P2（后续）**
5. 校准会：HR 复核节点 + 九宫格（自评 × 主管评）
6. 多期对比（同一人跨期趋势）
7. 匿名申诉/反馈入口
8. 拆分 `answers` 为明细表，支持逐条统计与题目级分析

## 13. 风险与未决问题

| 问题 | 影响 | 建议 |
|---|---|---|
| 员工入口公开，理论上可代填 | 数据可信度 | 加统一口令或对接企业微信身份 |
| 手机号作为身份，换号即两份档案 | 重复记录 | 后台支持"合并记录" |
| 主管链接转发外泄 | 越权评价 | token 可重置；后续加登录 |
| 口语化例证难以量化 | 分析价值 | 后续做文本标签/关键词提取 |
| 公司名与价值观条文随仓库公开 | 信息外泄 | 若要公开仓库，先替换为占位内容 |

## 14. 附录

### A. 考核内容

6 个价值观 × 5 级行为锚定，共 30 条，原文见 `content.py`。顺序为：客户第一、团队合作、拥抱变化、诚信、激情、敬业。

### B. 导出版式规格

- A4 纵向，边距 上下 9/8mm、左右 8mm
- 表格 6 列：序号 8mm ｜ 评估说明 158mm ｜ 自评 9mm ｜ 主管评 10mm ｜ 综合 9mm
- 每个价值观：深蓝标题条 + 5 行行为 + 1 行横向例证（自评 / 主管评各一半）
- 打印缩放：`fitToWidth=1, fitToHeight=1`，保证单页
